To guarantee that an algorithm like A* finds the optimal path, its heuristic function $h(n)$ must meet specific criteria depending on how the search is executed.

Here is how to check if a heuristic is **admissible** (required for Tree Search) and **consistent** (required for Graph Search).

## 1. Admissibility (For Tree Search)

A heuristic is **admissible** if it is optimistic. It must _never overestimate_ the true cost to reach the goal node from the current node.

### The Condition

For every node $n$:

$$0 \le h(n) \le h^*(n)$$

Where:

- $h(n)$ is your estimated cost to the goal.
    
- $h^*(n)$ is the **true, optimal cost** from $n$ to the goal.
    

### How to Check It

Because you rarely know the true cost $h^*(n)$ in advance, you cannot usually check admissibility by calculating the exact numbers. Instead, you prove it logically using **problem relaxation**:

1. **Identify the constraints** of your problem (e.g., in a sliding tile puzzle, a tile can only move into an adjacent empty space).
    
2. **Relax the problem** by removing one or more constraints (e.g., assume a tile can jump directly to its target position, ignoring other tiles).
    
3. **Calculate the exact cost** of this relaxed problem.
    
4. **Verify the logic:** Because the relaxed problem has fewer restrictions, its optimal cost will always be less than or equal to the real problem's cost. Therefore, this relaxed cost is a guaranteed admissible heuristic.
    

**Example:** In pathfinding, straight-line (Euclidean) distance is admissible because the shortest physical path between any two points is a straight line. No real-world path around obstacles can possibly be shorter than the straight line.

## 2. Consistency (For Graph Search)

A heuristic is **consistent** (or monotonic) if its estimate from the current node is no greater than the cost of taking a step to a neighboring node plus the estimated cost from that neighbor to the goal.

### The Condition

For every node $n$ and every successor $n'$ generated by an action $a$:

$$h(n) \le c(n, a, n') + h(n')$$

Where:

- $c(n, a, n')$ is the exact step cost of going from $n$ to $n'$.
    
- The goal node $G$ must have a heuristic value of zero: $h(G) = 0$.
    

This is essentially the **triangle inequality**: the estimated cost of the direct route $h(n)$ cannot be greater than the cost of a route that goes through a neighboring node $n'$.

### How to Check It

To check if a heuristic is consistent, apply the triangle inequality test to an arbitrary step:

1. Pick a generic node $n$ and an adjacent node $n'$.
    
2. Determine the maximum possible drop in the heuristic value: $h(n) - h(n')$.
    
3. Check if this drop is less than or equal to the actual step cost $c(n, a, n')$.
    
4. If the heuristic value never drops by an amount greater than the actual cost incurred, it is consistent.
    

**Example:** If taking one step costs 1, your heuristic value cannot drop by 2. If you move one tile, you are at most one step closer to the goal, so $h(n)$ should only decrease by a maximum of 1.

## Summary Comparison

> Every consistent heuristic is also admissible, but an admissible heuristic is not necessarily consistent.

# Example

We will define a graph, calculate the true optimal costs, and then test two different heuristic functions: one that is perfectly valid (consistent and admissible) and one that is flawed (admissible but inconsistent).

## 1. The Graph Setup

Imagine a graph with four nodes: **S** (Start), **A**, **B**, and **G** (Goal).

The exact step costs ($c$) between connected nodes are:

- $S \rightarrow A = 1$
    
- $S \rightarrow B = 4$
    
- $A \rightarrow B = 2$
    
- $A \rightarrow G = 6$
    
- $B \rightarrow G = 2$
    

![Pasted image 20260523012436.png](/img/user/imgs/Pasted%20image%2020260523012436.png)

First, we must determine the **true optimal cost to the goal**, $h^*(n)$, for every node. By tracing the paths, we find the cheapest routes to G:

- $h^*(G) = 0$ (Already at the goal)
    
- $h^*(B) = 2$ (Path: B $\rightarrow$ G)
    
- $h^*(A) = 4$ (Path: A $\rightarrow$ B $\rightarrow$ G is cheaper than the direct A $\rightarrow$ G route)
    
- $h^*(S) = 5$ (Path: S $\rightarrow$ A $\rightarrow$ B $\rightarrow$ G)
    

## 2. Defining the Heuristics

Let's evaluate two different proposed heuristic functions, $h_1$ and $h_2$, to see if they are admissible and consistent.

|**Node**|**True Cost (h∗)**|**Heuristic 1 (h1​)**|**Heuristic 2 (h2​)**|
|---|---|---|---|
|**S**|5|4|4|
|**A**|4|3|4|
|**B**|2|1|1|
|**G**|0|0|0|

## 3. Checking Admissibility

**The Rule:** For every node $n$, $h(n) \le h^*(n)$.

**Testing $h_1$:**

- S: $4 \le 5$ (Pass)
    
- A: $3 \le 4$ (Pass)
    
- B: $1 \le 2$ (Pass)
    
- G: $0 \le 0$ (Pass)
    

> **Result:** $h_1$ is **admissible**. It never overestimates the true cost.

**Testing $h_2$:**

- S: $4 \le 5$ (Pass)
    
- A: $4 \le 4$ (Pass)
    
- B: $1 \le 2$ (Pass)
    
- G: $0 \le 0$ (Pass)
    

> **Result:** $h_2$ is also **admissible**.

Because both heuristics are admissible, using either of them with A* in a **Tree Search** (where algorithms don't keep a memory of visited nodes) will guarantee finding the optimal path.

## 4. Checking Consistency

**The Rule:** For every edge from $n$ to $n'$, $h(n) \le c(n, n') + h(n')$.

_(The estimated cost from $n$ cannot exceed the step cost to a neighbor plus the estimated cost from that neighbor)._

**Testing $h_1$:**

We must check every single edge in the graph.

- **$S \rightarrow A$:** $4 \le 1 + 3 \implies 4 \le 4$ (Pass)
    
- **$S \rightarrow B$:** $4 \le 4 + 1 \implies 4 \le 5$ (Pass)
    
- **$A \rightarrow B$:** $3 \le 2 + 1 \implies 3 \le 3$ (Pass)
    
- **$A \rightarrow G$:** $3 \le 6 + 0 \implies 3 \le 6$ (Pass)
    
- **$B \rightarrow G$:** $1 \le 2 + 0 \implies 1 \le 2$ (Pass)
    

> **Result:** $h_1$ is **consistent**. The heuristic value never drops faster than the actual cost spent taking a step.

**Testing $h_2$:**

Let's check the edges using $h_2$.

- **$S \rightarrow A$:** $4 \le 1 + 4 \implies 4 \le 5$ (Pass)
    
- **$A \rightarrow B$:** $4 \le 2 + 1 \implies 4 \le 3$ (**FAIL**)
    

> **Result:** $h_2$ is **inconsistent**.

Look at the failure on edge $A \rightarrow B$. At node A, the heuristic estimated you were 4 units away from the goal. You took a step to B that cost 2 units. Suddenly, at node B, the heuristic says you are only 1 unit away.

Your estimated cost dropped by 3, but you only spent 2. This violates the triangle inequality and creates a "funnel" that can trick A* during a Graph Search into thinking it found an optimal route to a node when it hasn't, causing it to lock in a suboptimal path.

# How will that happen ?

To understand how A* fails here, we need to look at two critical mechanics of Graph Search:

1. **The $f$-cost formula:** A* always expands the node with the lowest $f(n)$, where $f(n) = g(n) + h(n)$. ($g$ is the exact cost spent so far, $h$ is the estimated cost to the goal).
    
2. **The Closed List (The Golden Rule of Graph Search):** Once a node is expanded (its neighbors are checked), it is moved to the Closed List. **Standard Graph Search will never expand a node in the Closed List again**, assuming the first time it reaches a node is via the most optimal path.
    

With our inconsistent heuristic ($h_2$), that assumption breaks. Here is the step-by-step trace of how it happens.

### The Setup

- **Costs ($c$):** S→A = 1, S→B = 4, A→B = 2, A→G = 6, B→G = 2
    
- **Heuristic ($h_2$):** S = 4, A = 4, B = 1, G = 0
    
- **True Optimal Path:** S $\rightarrow$ A $\rightarrow$ B $\rightarrow$ G (Cost: 5)
    

### Step 1: Expand the Start Node (S)

A* begins at S and looks at its neighbors, A and B. It calculates their $f$-costs to decide which to explore next.

- **Path S $\rightarrow$ A:**
    
    - $g(A)$ = 1
        
    - $h(A)$ = 4
        
    - $f(A)$ = 1 + 4 = **5**
        
- **Path S $\rightarrow$ B:**
    
    - $g(B)$ = 4
        
    - $h(B)$ = 1
        
    - $f(B)$ = 4 + 1 = **5**
        

**State:**

- **Frontier (Open List):** A ($f=5$), B ($f=5$)
    
- **Closed List:** { S }
    

### Step 2: The Trap (Expanding B)

A* picks the node from the Frontier with the lowest $f$-cost. Because A and B are tied at 5, A* can pick either. Let's follow what happens when it picks **B**.

A* removes B from the Frontier and expands it. Look at B's neighbor, G.

- **Path S $\rightarrow$ B $\rightarrow$ G:**
    
    - $g(G)$ = 4 + 2 = 6
        
    - $f(G)$ = 6 + 0 = **6**
        

**State:**

- **Frontier:** A ($f=5$), G ($f=6$)
    
- **Closed List:** { S, **B** } <-- _This is the fatal mistake. A_ has locked in the cost to reach B as 4.*
    

### Step 3: The Missed Opportunity (Expanding A)

A* looks at the Frontier and picks **A**, because its $f$-cost (5) is lower than G's (6).

It removes A from the Frontier, moves it to the Closed List, and checks A's neighbors: G and B.

- **Path S $\rightarrow$ A $\rightarrow$ G:**
    
    - $g(G)$ = 1 + 6 = 7.
        
    - $f(G)$ = 7 + 0 = 7. (This is worse than our existing path to G, so we ignore it).
        
- **Path S $\rightarrow$ A $\rightarrow$ B:**
    
    - $g(B)$ = 1 + 2 = **3**.
        

**The Failure:** A* just found a cheaper way to reach B! Going through A only costs 3, while the previous path directly to B cost 4.

However, because B is already in the **Closed List**, standard Graph Search ignores this new path. It strictly obeys the rule: _never reopen a closed node_. It throws away the optimal route to B.

**State:**

- **Frontier:** G ($f=6$ via B)
    
- **Closed List:** { S, B, A }
    

### Step 4: Reaching the Goal

A* expands G. Since G is the goal, the search terminates.

- __A_ Final Result:_* S $\rightarrow$ B $\rightarrow$ G (Cost: **6**)
    
- **True Optimal Path:** S $\rightarrow$ A $\rightarrow$ B $\rightarrow$ G (Cost: **5**)
    

## Why did this happen?

The root cause is a lack of **monotonicity**.

If a heuristic is consistent, the $f$-value will always stay the same or increase as you walk down a path. It never drops. Because the $f$-value never drops, A* processes nodes in expanding "contours" of cost, guaranteeing that the first time it reaches a node, it has found the absolute cheapest path to it.

Look at the $f$-values along the true optimal path using our inconsistent $h_2$:

1. Node S: $f(S) = 0 + 4 = \mathbf{4}$
    
2. Node A: $f(A) = 1 + 4 = \mathbf{5}$
    
3. Node B: $f(B) = 3 + 1 = \mathbf{4}$ _(Wait, the $f$-cost went down!)_
    

Because the heuristic value at A was artificially inflated compared to B, it created a "bump" in the $f$-costs. A* looked at A, saw an $f$-cost of 5, and incorrectly assumed that exploring the direct, suboptimal path to B (which also had an $f$-cost of 5) was a safe bet. It locked B into the Closed List before realizing A was hiding a shortcut.
